## 原生应用预检

原生应用过去会忽略 `expected`，造成 dry-run 未保存的新提示词也被判为通过。本版将 expected 传入原生预检和提交入口，逐项检查当前保存状态及真正解析的绑定值。

- `expected.appInputs` 使用内部输入 `nodeId` + `fieldName`，检查值和/或源节点；显式 null 表示无绑定，保留值类型。
- `expected.prompt` 多文本字段时必须给 `promptField`，避免猜错提示词位置。
- 兼容 `expected.params.inputs`；原生其余设置仅检查 `instanceType`、`apiKeyMode`、`generateNum`。未知、含糊或重复字段返回结构化错误。
- `expected.references` 检查完整媒体映射。未通过的预检返回 `digest:null`；只有通过的 digest 可固定后续提交。
- 参数 dry-run 保持未保存状态；预检、提交及变更后的 digest 校验使用同一规则。普通模型的原有 expected 语义保留。

准确参数和示例见 [Agent 指南](../../AGENT_QUICKSTART.md#原生应用预检的-expected0109)。

## 隧道恢复和主机分工

- 可选 `--restart-stalled` 仅在持续失去成功云端轮询、有新鲜运行证据且所有在途工作空闲时重启原 alias。先确认旧进程停止再重连；连续失败最多3次，避免重启循环。
- 跨平台 `tunnel-manager.mjs` 沿用现有 tunnel ID、runtime key 文件和 profile，显式继承该隧道保存的网络环境。
- 自动更新识别本安装拥有的运行中 alias，在换版时停止旧 MCP 子进程并等待桥接恢复后重连；已停止的 alias 保持停止。配置与授权不在安装目录中。
- ChatGPT 专用隧道和公网 HTTP 网关可以在不同主机运行。希望 Mac 合盖后仍可使用插件时，应将专用隧道部署到常开主机。

## 验证

离线复现、Yjs 保存/预演、实际原生输入一致性检查、错误恢复提示、隧道退避与重启顺序均有回归。实际节点使用只读检查：不匹配的预期被拒绝，匹配值通过，16 个输入的前后哈希一致；没有提交生成。

安装和回退说明见 [安装指南](../../AGENT_INSTALL.md)。已有客户端若继续驻留旧 stdio 进程，重连工具即可加载新 schema，授权沿用。
