# 0.10.7 · 原节点历史修复、应用复用与调用提速

2026-10-22 · 83 个 MCP 工具 · macOS / Windows

本次正式发布包含此前未公开发布的 0.10.4–0.10.6 累计改进。现有配置和 OAuth 授权继续沿用，普通升级无需重新关联账号。

## 原节点历史修复

- 对已记录的 **301 历史路由冲突**，`rh_sync_node_history` 新增 `repairRoute`：先预览，核验每条真实 task、node 和 output，再按版本校验原地修复。
- 修复前保存私有快照；原节点保留真实历史批次、输出身份与恢复元数据，停用被拒绝的路由。当前视频、参数、参考、连线、排版和采用状态保持。
- 后续同步合并真实新旧历史，原版本仍可读取、选择；不删除远端记录，不借用其他节点的历史，不重新生成。复制独立节点时清除原节点的恢复身份。

## 项目制作与排版

- 非临时项目直接使用画布原生应用，**同一 P 持续复用一个节点**，各轮结果保留在原生历史中。
- `productionKey` 提供稳定制作身份；重复准备可返回已存在节点，不重置其素材和参数。
- 模板 v3 默认每行两个板块、板块内每行四个 P，按真实横竖画幅和行高排布。旧间距与画布专属设置继续保留。
- 修正历史切换后沿用旧媒体尺寸、分组坐标和成员检查；明确淘汰单次结果时保留可继续使用的 P 应用。

## 连接恢复与效率

- 四个独立浏览器任务槽、长轮询、合并路由查询、批量节点读取和媒体尺寸缓存，减少串行等待与重复读取。
- 提交响应丢失时保留原请求编号，只恢复回执；失效回执不再长期占用任务槽。过期但尚未派发的请求可正常结束。
- 写入断线或结果未知时保留明确状态，不自动重发。诊断区分后台、MCP、扩展和页面运行时的已加载版本与指纹。
- 模型查询接受 `video`、`image`、`audio`、`text` 分类，兼容大小写和连字符，避免模型筛选参数校验失败。
- 报价绑定具体输入和预检摘要；付费或费用未知的媒体处理继续使用现有用户授权流程。

## 升级方式

已开启自动更新的正式安装会在空闲时升级；也可在安装目录运行 `node scripts/rh-update.mjs apply`。源码工作区不由自动更新器覆盖。

升级后使用 `rh_status` 检查后台、MCP、扩展和运行时。已登记扩展可自动重载；旧版 MCP 客户端若仍显示旧参数，刷新工具列表或重连即可。独立管理的 ChatGPT 隧道运行副本需按其部署方式同步更新，保留原配置和密钥引用。

安装不会自动改动既有画布。历史路由修复使用 `repairRoute: true` 的预览和执行流程，带准确原节点及返回的 `expectedRevisions`。只有一条真实结果时保留真实数量。
