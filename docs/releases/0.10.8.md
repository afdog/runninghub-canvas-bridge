# 0.10.8 · 减少重复开页，明确恢复路径，提升调用效率

2026-10-23 · 83 个 MCP 工具 · macOS / Windows

本版沿用现有配置、浏览器登录和 OAuth 授权，普通升级无需重新关联账号。

## 六项改进

1. **复用页面**：识别已打开和正在加载的画布/目录页；同画布并发连接合并执行，每个调用保留自己的回执。默认优先沿用已连接的浏览器，明确指定浏览器时遵从指定。
2. **停止无效循环**：永久历史冲突进入可查看的阻塞状态；临时错误有次数和时长上限。页面断开等待重连，不靠反复开页恢复。原任务与回执保留，修复后可通过 `resumeBlocked` 精确恢复。
3. **统一回执恢复**：优先使用 `rh_command_result`，兼容 `rh_recover_command`。返回的原始回执 ID 可脱离在线画布查询；逻辑请求 ID 仍需准确的原画布 URL。查询失败保留原身份，不重发未知生成。
4. **减少无关阻塞**：生成预检与提交校验目标节点及实际上游依赖；其他节点或纯排版修改不再使预检失效。参数、参考、历史冲突和费用授权检查保留。
5. **工具选择更清晰**：错误返回推荐恢复工具、已知参数、缺少的输入和重试策略；保留全部工具的兼容入口。
6. **读取更轻**：模型/应用元数据按页面、账号和团队缓存 30 秒，合并并发请求并支持 `refresh`；节点可按 `inputs`、`outputs`、`history` 读取，默认完整返回。提示词不截断，应用修改直接返回最新 revision，诊断复用未变化文件的指纹。

## 升级与使用

已启用自动更新的正式安装在空闲时升级；手动运行 `node scripts/rh-update.mjs apply` 使用相同的校验与恢复机制。源码工作区继续按 Git 更新，不被自动覆盖。

使用 `rh_status` 核对后台、MCP、扩展和页面运行时。已登记的扩展会在空闲时自动重载；仍驻留旧进程的 stdio 客户端需重连。独立的 ChatGPT 隧道运行副本需同步版本路径，保留原连接和密钥引用。

已有永久冲突队列会显示为 blocked，原记录保留。修复具体节点后才显式恢复同步。升级不提交生成，也不整理或删除已有画布内容。
